# MakeAI License Server — Complete Build Specification

> **Standalone micro-service spec** — author-hosted purchase code verification server for
> MakeAI core + all CodeCanyon addons. Pairs with master prompt P03 (updated) and
> Addon Guide § 4.1. Written for DeepSeek implementation.
>
> **Deployment target:** any small VPS — Oracle Cloud Free Tier ARM is sufficient.
> **Domain:** `license.yourdomain.com` (HTTPS mandatory, Let's Encrypt)

---

## 1 — PURPOSE & SCOPE

A single-tenant micro-service owned by the author. It does exactly four things:

1. **Verifies** Envato purchase codes against the Envato API using the author's personal token (which never leaves this server)
2. **Maps** product slugs → Envato item IDs (authoritative — shipped products never contain enforced item IDs)
3. **Signs** every response with an Ed25519 private key so buyer installations can authenticate responses
4. **Logs** verifications for abuse detection (one code on many domains) and provides a revocation kill switch

**Out of scope:** payments, user accounts for buyers, downloads, update delivery. Keep it tiny.

## 4 — DATABASE

### Migration: `create_products_table`

```sql
products
  id              bigint PK
  slug            varchar(100) UNIQUE NOT NULL   -- 'makeai', 'ai-assistant', 'whatsapp-chatbot'...
  name            varchar(150) NOT NULL
  type            enum('core','addon') NOT NULL
  envato_item_id  bigint UNIQUE NOT NULL         -- from CodeCanyon dashboard after upload
  is_active       boolean DEFAULT true           -- pause verification per product
  created_at, updated_at
```

### Migration: `create_revocations_table`

```sql
revocations
  id              bigint PK
  purchase_code   char(36) NOT NULL              -- plaintext is OK here: author's private server,
  product_id      bigint FK → products NULL      --   and the code itself is the lookup key
  reason          varchar(255) NULL              -- 'refund abuse', 'shared publicly', ...
  revoked_by      varchar(100) NULL
  created_at, updated_at
  UNIQUE (purchase_code, product_id)             -- product_id NULL = revoked for ALL products
```

### Migration: `create_verification_logs_table`

```sql
verification_logs
  id              bigint PK
  product_slug    varchar(100) INDEX
  purchase_code_hash char(64) INDEX              -- sha256 — logs don't need plaintext
  domain          varchar(255) INDEX
  ip              varchar(45)
  result          enum('valid','invalid_format','not_found','wrong_item',
                       'refunded','revoked','envato_error')
  envato_buyer    varchar(100) NULL
  license_type    tinyint NULL                   -- 1 | 2
  created_at
  INDEX (purchase_code_hash, domain)
  INDEX (created_at)
```

> Prune logs older than 12 months via daily `schedule` task (no Horizon — plain cron `schedule:run`).

## 5 — THE VERIFY ENDPOINT

### Route

```php
// routes/api.php
Route::post('/v1/verify', VerifyController::class)
    ->middleware('throttle:verify');             // named limiter, Section 5.4
```

Full URL: `POST https://license.yourdomain.com/api/v1/verify`

### 5.1 Request contract

```json
{
  "product":        "core",                                  // "core" | "addon"
  "slug":           "makeai",
  "purchase_code":  "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "domain":         "buyersite.com",
  "version":        "1.0.0"
}
```

Validation: `product` in:core,addon · `slug` required string max:100 · `purchase_code`
required string max:50 · `domain` required string max:255 · `version` nullable string max:20.

### 5.2 Response contract (always HTTP 200 — result is in the payload)

```json
{
  "payload": {
    "valid":           true,
    "slug":            "makeai",
    "item_id":         51234567,
    "license_type":    2,
    "buyer":           "envato_username",
    "purchased_at":    "2026-05-01T10:00:00Z",
    "supported_until": "2026-11-01T10:00:00Z",
    "verified_at":     "2026-06-12T08:00:00Z",
    "error":           null
  },
  "signature": "base64-ed25519-detached-signature"
}
```

On failure `valid:false`, all data fields `null`, and `error` is one of:
`invalid_format | not_found | wrong_item | refunded | revoked | envato_error`

**Signing — the exact byte contract (both sides MUST match):**

```php
$json      = json_encode($payload, JSON_UNESCAPED_SLASHES);  // sign exactly these bytes
$signature = base64_encode(sodium_crypto_sign_detached(
    $json,
    base64_decode(config('license.private_key'))
));
return response()->json(['payload' => $payload, 'signature' => $signature]);
```

Client side (MakeAI core / addon service) must verify against
`json_encode($payload, JSON_UNESCAPED_SLASHES)` of the *received* payload —
re-encode, don't re-order keys. Server controls key order; client never modifies payload
before verification.

### 5.3 Controller logic — `app/Http/Controllers/Api/VerifyController.php`

```php
public function __invoke(VerifyRequest $request, EnvatoClient $envato, ResponseSigner $signer)
{
    // 1. FORMAT — local regex check, no Envato call
    //    /^[0-9a-f]{8}-([0-9a-f]{4}-){3}[0-9a-f]{12}$/i  → fail('invalid_format')

    // 2. PRODUCT — Product::where('slug', $slug)->where('is_active', true)->first()
    //    not found → fail('not_found')   // don't leak which slugs exist

    // 3. REVOCATION — check revocations for this code where product_id matches OR is NULL
    //    found → fail('revoked')

    // 4. ENVATO — cached 10 min per code (Cache::remember("envato.{$codeHash}", 600)):
    //    GET https://api.envato.com/v3/market/author/sale?code={code}
    //    Authorization: Bearer {ENVATO_PERSONAL_TOKEN}
    //    timeout 15s, retry(2, 500)
    //    HTTP 404            → fail('not_found')
    //    network/5xx error   → fail('envato_error')   // client treats as transient
    //    response.refunded   → fail('refunded')       // field: ['refunded'] boolean? — Envato
    //                                                  // marks refunds; also check 'sold_at' exists

    // 5. ITEM MATCH — response['item']['id'] !== $product->envato_item_id → fail('wrong_item')

    // 6. LICENSE TYPE — str_contains(response['license'], 'Extended') ? 2 : 1

    // 7. LOG — VerificationLog::create([... result: 'valid', sha256 code hash ...])
    //    (every branch above also logs its result before returning)

    // 8. SIGN + RETURN payload per § 5.2
}
```

`fail($error)` = build `valid:false` payload with that error, log it, sign it, return it.
**Every response is signed, including failures** — otherwise a fake server could return
unsigned failures to confuse buyers, and clients couldn't distinguish real invalidations
(which start the 72h grace) from spoofed ones.

### 5.4 Rate limiting

```php
// AppServiceProvider::boot()
RateLimiter::for('verify', fn (Request $r) => [
    Limit::perMinute(10)->by($r->ip()),
    Limit::perMinute(20)->by($r->input('purchase_code', $r->ip())),
]);
```

Throttled requests get standard 429 — buyer-side `AddonLicenseService` already shows
"Could not reach license server — try again" on non-200.

## 6 — KEY MANAGEMENT

### Artisan command: `php artisan license:keys`

```php
// app/Console/Commands/GenerateLicenseKeys.php
// 1. $pair = sodium_crypto_sign_keypair();
// 2. Print base64 secret key + base64 public key
// 3. Refuse to run if LICENSE_SIGNING_PRIVATE_KEY is already set (require --force)
//    — accidental rotation invalidates every shipped MakeAI install
```

**Key lifecycle rules:**
- Generate ONCE before first MakeAI release. Private key stays in this server's `.env` + one offline backup (password manager). It is never transmitted anywhere.
- Public key is pasted into MakeAI core: `LicenseService::LICENSE_SERVER_PUBLIC_KEY` and `AddonLicenseService::LICENSE_SERVER_PUBLIC_KEY` (same key for both).
- Rotation = breaking change requiring a MakeAI core update. Avoid. If the private key ever leaks, rotate immediately and ship a core patch release.

## 8 — ADMIN PANEL (Inertia + Vue, MakeAI design tokens)

Single admin (seeded from `.env`), session auth, no registration route. Four pages:

### 8.1 Dashboard — `/admin`
- Stat cards: verifications today / 7d, unique domains 7d, invalid rate %, top product by verifications
- **Abuse flags table** (computed query, no extra table): purchase codes seen on **> 5 distinct domains in 30 days** —
  ```sql
  SELECT purchase_code_hash, COUNT(DISTINCT domain) AS domains, MAX(created_at) AS last_seen
  FROM verification_logs WHERE created_at >= NOW() - INTERVAL 30 DAY AND result = 'valid'
  GROUP BY purchase_code_hash HAVING domains > 5 ORDER BY domains DESC
  ```
  Each row → "Revoke" action (needs the plaintext code — admin pastes it; hash shown for matching)

### 8.2 Products — `/admin/products`
- CRUD table: slug, name, type (core/addon), envato_item_id, active toggle
- **This is the page used in the per-addon release workflow:** upload to CodeCanyon → copy item ID from dashboard URL → add row here → done
- Validation: slug unique, item_id unique, slug immutable after creation (shipped products reference it)

### 8.3 Revocations — `/admin/revocations`
- Add revocation: purchase code (UUID-validated), product (dropdown incl. "All products"), reason
- List with delete (un-revoke)
- Confirmation modal on add: "Buyer installs using this code will be deactivated within 7 days (next re-verify) plus a 72h grace period."

### 8.4 Logs — `/admin/logs`
- Paginated, filterable by: product slug, result, domain, date range
- Code hash shown truncated; full row detail in slide-over

## 10 — SECURITY CHECKLIST

- [ ] HTTPS only — HTTP requests redirected; HSTS header set
- [ ] `ENVATO_PERSONAL_TOKEN` and private key only in `.env`; `.env` perms 600; never in repo
- [ ] Every response signed, including failures (§ 5.3)
- [ ] Rate limiting active on `/api/v1/verify` (IP + purchase code dimensions)
- [ ] Admin routes behind auth + `throttle:5,1` on login; no registration/forgot-password routes
- [ ] Verification logs store code **hash**, never plaintext
- [ ] CORS: API endpoint accepts requests from any origin (buyer servers call server-to-server; no browser CORS involved) — but reject requests with `Origin` header present? **No** — keep it simple: server-to-server only is enforced by nothing being browser-callable-useful; do not add CORS headers
- [ ] Error responses never reveal whether a slug exists (`not_found` for unknown slug and unknown code alike)
- [ ] `php artisan license:keys` refuses overwrite without `--force`

## 12 — DEPLOYMENT (Oracle Free Tier ARM or any small VPS)

```
1. Ubuntu 24 + Nginx + PHP 8.3-fpm (ensure php8.3-sodium present) + MySQL 8
2. git clone → composer install --no-dev → npm ci && npm run build
3. cp .env.example .env → fill ENVATO_PERSONAL_TOKEN, admin credentials
4. php artisan key:generate && php artisan license:keys   → copy PUBLIC key out
5. Paste public key into MakeAI core (both LicenseService and AddonLicenseService constants)
6. php artisan migrate --force && php artisan db:seed     → seeds admin + 'makeai' core product
7. Certbot: https for license.yourdomain.com
8. Cron: * * * * * php /var/www/license/artisan schedule:run
9. Add the 'makeai' core product's envato_item_id after CodeCanyon upload (Admin → Products)
10. Smoke test: curl POST /api/v1/verify with a real purchase code → verify signature locally
```

**Uptime note:** buyer installs tolerate downtime gracefully (network failures never
invalidate licenses — only signed `valid:false` does), but first-time activations fail while
the server is down. A simple uptime monitor (UptimeRobot free tier) on `/api/v1/verify`
health is recommended. Optionally add `GET /up` (Laravel's built-in health route) for the monitor.
